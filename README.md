# 组织变更后的层级预算分解与支出占额

纯 Python 3.11 + 标准库（`sqlite3`）实现，无第三方依赖。两个服务物理分离、
仅通过**已发布的不可变组织产品版本**衔接，解决部门迁移后旧预算与已承诺
支出在新旧上级同时占额的问题。所有金额均为整数分。

## 目录结构

```
orgbudget/
  errors.py          领域异常（组织错误与预算错误各自成体系）
  budget.py          纯函数分解：按权重大数余数法（下取整 + 余数降序 + ID 并列）
  org_service.py     组织编制服务：唯一根父子树、子树移动、叶停用、不可变版本快照
  budget_service.py  预算执行仓：根预算、权重分解、承诺、实际支出、换版与覆盖校验
  roster.py          封样名册模型：具名纸票、原票归层、确定性摘要（纯函数）
  sampling.py        内审抽查求解器：最不利分布下的最低发现概率、最省配额
  audit.py           独立重算审计（Fraction 独立实现 + 直接读原始事件表核对）
demo/
  scenarios.py       七个端到端案例，可直接复跑
tests/               60 个 unittest 用例（含跨进程争用、2000 组模糊交叉核对）
```

## 运行

```bash
python3 -m unittest discover -s tests -v   # 测试
python3 -m demo.scenarios                  # 端到端演示，产物落在 demo_data/*.db
```

## 核心规则与实现落点

### 组织编制服务（`OrgService`，独立 SQLite 库）

- 唯一 `department_id`、唯一根、父子树；建部门 / 移动完整子树 / 停用叶部门。
- 移动只改被移动节点一条父边：天然是整棵子树移动，不存在“部分移动”；
  根不可移动，挂到自身或子孙下报 `CycleError`，发布时 `OrgProduct` 构造器
  再做单根 / 无环 / 唯一父项全量校验。
- 每次 `publish()` 把全量快照写入 `org_dept`，版本号严格递增；
  **已发布产品不可变**，后续移动只产生新版本，旧版本行永不更新。
- 组织维护独立于预算，行政客户可直接用祖先 / 后代 / 子树查询。

### 预算执行仓（`BudgetService`，另一个独立 SQLite 库）

- 每个方案在 `scheme` 表明确绑定一个组织产品版本；预算端查询时按方案绑定
  的版本实时向组织服务读取**本次产品**，不缓存旧树，迁移部门不可能出现
  两份额度。
- 分解（`budget.allocate_children`）：按权重比例下取整，丢掉的分按小数余数
  降序补，余数并列按部门 ID 升序；恒有 `Σ孩子预算 = 父预算`。
- 叶可用额 = 分配预算 − 实际支出 − 未结承诺剩余，开立承诺时在事务内校验，
  不得为负；支出仅追加，不得超过承诺剩余；取消只释放剩余，已支出不可撤销。
- 承诺 `request_no` 是全局唯一幂等键，支出事件有独立幂等键，丢响应重试
  不二次占额；同键不同内容报 `IdempotencyConflict`。
- 换版 `revise_budget()`：预算人员为**新产品**的每条直接父子边补齐正权重
  （缺边 / 多边均拒绝），自根向下重算全部预算，再用全部历史承诺 / 支出
  事件做覆盖校验。任一叶覆盖不了“实际支出 + 未结承诺剩余”则整次换版
  回滚并在 `rejected_revision` 留痕；**承诺的部门身份永不改写**。
- 拒绝不影响组织服务已发布的新产品，预算仓继续绑定旧版。
- 汇总沿方案绑定产品的树闭包计算；旧方案查询永远沿旧树，不按当前树解释历史。

### 并发与持久化

- 所有写操作在单连接 `BEGIN IMMEDIATE` 事务内完成“读取校验 → 写入”，
  SQLite 写锁把并发提交串行化；测试覆盖线程与**独立进程**两种争用，
  两个连接争同一剩余额时最多一方成功。
- 全部状态落 SQLite 文件，服务重启后事实完整可读。

### 独立审计（`audit.audit_scheme`）

刻意不调用生产代码的分解 / 汇总路径：

1. 直接 SQL 读组织快照、承诺与仅追加支出事件；
2. 用 `fractions.Fraction` 重新推导分解，与落库分配逐部门比对；
3. 从原始事件重建每叶实际支出与未结占额，逐级核对守恒、覆盖、可用额非负、
   祖先汇总 = 后代叶事实之和。2000 组随机参数下两套实现结果完全一致；
   直接篡改分配或事件表会被审计抛出 `InvalidTree`。

## 封样名册与内审抽查

内审把**同一张原票装成一封**，避免把一纸票的多行分录误当多张票而高估
“发现问题”的概率。相关实现分布在 `roster.py`（纯模型）、`sampling.py`
（求解器）与 `audit.audit_roster`（独立复点）。

### 归票与冻结（`BudgetService`）

- `register_ticket(ticket_id)` 登记具名纸票；`assign_spend(idem_key, ticket_id)`
  把一条**已实际入账**的 `spend` 事件归到纸票（幂等键不存在即
  `SpendEventNotFound`，因此**只有已入账事件能入封**，承诺本身不是票）。
- 一条支出事件在同一切面恰好归一张票；重复归同一票是幂等空操作，
  改挂另一票须显式 `reassign_spend`（勘误），否则报 `TicketConflict`。
- `seal_roster(org_version)` 冻结签发名册：若仍有已入账支出未归票则拒绝
  （`IncompleteRoster`），**不签发残缺名册**；一次冻结绑定一个**已发布
  组织版本**，之后勘误归票 / 迁移实付部门 / 新增支出都不会改动旧名册，
  再冻结才产生新名册，旧名册用 `get_roster(roster_id)` 原样重开。
- 原来取消承诺的**已付部分**仍要入册：取消只释放剩余占额，`spend` 仅追加。

### 归层规则

对每张原票，沿**该名册绑定的组织产品**取全部实付部门：

- 若它们全部落在根的**同一个直接分部**之下 → 归该分部层；
- 若跨两个及以上直接分部 → 归**“联合”层**（`JOINT_LAYER`）；
- 同一纸票始终只有一封；`RosterEnvelope` 记录封内支付、`basis`（归层依据）
  与层内封号，层按直接分部 ID 升序、联合层固定最后，各层给出封数。

名册摘要 `cut_digest` 只编码支付集合本身（排序后确定性 SHA-256），
对同一批实付恒定；封的归组变化体现在封行里，不改变摘要。

### 抽查配额（`sampling.solve_quota` / `plan_for_roster`）

- 输入各层封数（≤4 层、每层 ≤12 封）、每层每开一封成本、整批恰有的问题
  封数 `k`、要求的最低发现概率 `p`（`Fraction` 有理数）。
- 每层独立等概率不放回抽固定数目的**不同封**。对一种问题封分布，一层
  漏检概率为 `C(n−y, x)/C(n, x)`，各层独立相乘即整批漏检概率。
- **在所有可能的问题封分布中都必须达到 p**：对每个候选配额用分组背包 DP
  求**最不利分布**（漏检乘积最大），要求其漏检概率 `≤ 1−p`；再在所有达标
  配额中取总成本最小，平手按层序与开封面数任取。
- 层内开 0 封或全开都作为合法边界参与枚举；p=1 时要求未开空位少于 `k`。
- 返回 `SamplingPlan`：各层配额、实际可选的层内封号、最不利分布
  `worst_misses`、整批最不利漏检概率与保证 `guarantee`（均为精确
  `Fraction`），便于工单执行前复核；`worst_case_miss()` 可独立核对任意配额。
- 联合层作为普通一层同样计入求解。

### 独立复点（`audit.audit_roster`）

只读原始表、不调用生产装封路径，重算并核对：每笔入册支付都对应真实
`spend` 事件；每条已入账支出恰归一封（不重不漏）；同一纸票恰一封且票间
不交叉；按绑定组织版本重算归层与落库一致；摘要可由支付行重算。篡改
名册部门 / 删除支付都会抛 `InvalidTree`。

## 演示案例（`python3 -m demo.scenarios`）

1. 三层树余分分配（含余数并列按 ID、不同余数两种情形，并与 Fraction 实现交叉核对）；
2. 带未结承诺的部门子树迁移、换版重算、身份不改、旧版沿旧树冻结；
3. 新预算不足被整次拒绝，组织新产品照发，预算仓继续绑旧版；
4. 支出后部分取消：已支出保留、剩余占额释放、取消后禁止再支出；
5. 并发承诺争额度最多一方成功、同请求重试不二次占额（线程级）；
6. 20 部门 / 深度 5 / 100 笔支出的大规模场景，迁移前后各做一次独立审计；
7. 封样与抽查小册：X 4 封 / Y 2 封、每封一件；成本 1/2、k=1、p=1/2 时最省
   2+1 封（费用 4）；把一片叶移到 Y 后仍六封、须 2+2 封（费用 6）；原组织
   p=2/3 时须 3+2 封（费用 7）；跨部门票归联合层；k>1 时“发现一封”概率
   不能简单相加。

范围限定：不做员工工资、现实预算制度或审批界面。
