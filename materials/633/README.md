case.json的比分始终按该match的主/客槽位，不直接附着球队；before_fixture每对一次、主客1/2平衡，flipped_match_ids同时翻三场得到另一合法赛程。scores固定，按两个真实edition解读应不同。所有时间/赛程为虚构；不提供排名或赛程目标代码。

本微型输入的完整映射：每轮唯一可用slot为s，容量均为slot_capacity=2；blackouts=[]表示所有球队无禁用slot。scores各行为state=played的摘要，稳定result_id取r-加match_id，按数组顺序组成一次原子初始批request_id=initial-results，引用同名match_id；score_home/score_away分别取home_goals/away_goals。该事实切面固定为此批提交后，无额外判罚。

## 旧场记簿逐球卡与制胜球奖务系统（新增）

在赛程服务与排名仓之上接入旧场记簿逐球卡，解决“只剩终场比分与涂改逐球记录时
能否发制胜球奖”的问题。同样一个终场比分，领过先又被追平与一路领先对应的制胜球
可以不同，因此不接受“最后一个进球就是制胜球”的猜测。

模块：

- `league/playbyplay.py`：纯函数解释引擎。逐球卡按具名序号排列、每卡一球、
  一或两个可能记入方；按当版主客与球员名册排除球队不符选择并留痕；累计检查点为
  硬约束。分层状态图（只存累计比分、不存排列）前向定首个无合法前缀卡、后向判
  终分可达（矛盾到终场才暴露标 `final`），并按“最后平局之后第一球”传播可能
  制胜卡集合，前驱指针线性重建两条完整见证。
- `league/awards.py`：球员奖/培训站奖判定三态——立即发证（所有解释同一收件者）、
  待核听审（真实收件争议或有人/无人并存，附两条见证）、不颁（平局/取消/不可解释/
  全部无人能领）。培训站按奖方自己的注册簿归并，未登记即无人能领。
- `league/tribunal.py`：听审排庭。合庭共传保管人一次、分庭各传；主席回避清单、
  主席与保管人不同且每人每天只在一庭；目标字典序为传卷最少→最早收完，支持传卷
  上限查询最快审完日。每批最多三场/六案/四主席/五天。
- `league/card_repo.py`：独立 SQLite 版本仓。卡卷/比分涂改另发新版、老版保留，
  request_id 幂等、非法整卷回滚；冻结解释与奖证落不可变快照，关账后凭同一份
  冻结产品按不同奖务登记重算排庭。
- `oracle_cards.py`：小域独立枚举 oracle（<=12 卡笛卡尔积），与分层引擎双向对照。
- `demo_cards.py`：端到端演示题面三球小例（P/Q 待核、订正发 P、同站 K 即发、
  检查点反例、关账重判、两案分/合庭传卷优化、取消场无凭单）。

运行：

```bash
python3 demo_cards.py                       # 逐球卡端到端演示（产物在 run_data_cards/）
python3 -m unittest discover -s tests       # 全部测试（原 38 + 新增 54 = 92 个）
```
